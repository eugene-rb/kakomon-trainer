# 解答用紙登録・解答解説自動対応付け 仕様書

| 項目 | 内容 |
|---|---|
| 版 | 1.0 |
| 作成日 | 2026-09-07 |
| 対象 | 模試自動採点システムの用紙登録機能 |
| 基準 | 現在の実装に基づく仕様 |

## 1. 目的と範囲

解答用紙と解答解説・採点基準をまとめて登録し、ファイル名の命名規則によって自動で対応付ける。用紙ごとの管理用IDの入力と、新しい設問を作成するたびに参照資料を選ぶ操作を減らす。

対象は、ファイルの選択、対応関係の確認、用紙・資料の保存、領域エディタへの引き継ぎとする。解答領域の指定、設問ごとの配点・採点形式・正答の設定は利用者が行う。

登録処理ではOCRやLLMを呼び出さない。既存アプリの起動条件は別途適用される。

## 2. 用語

| 用語 | 意味 |
|---|---|
| 解答用紙 | 印刷して記入するための白紙のPDF |
| 解答解説 | 模範解答や解説を含む参照資料 |
| 採点基準 | 配点や減点基準などを含む参照資料 |
| 共通名 | 同じ試験・科目・年度などを識別するファイル名の部分 |
| 登録グループ | 同じ共通名を持つ解答用紙1件と参照資料0件以上の組 |
| テンプレート | 登録した用紙、ページ情報、設問設定、参照資料のまとまり |
| 管理用ID | 保存先やURLでテンプレートを識別する内部の名前 |

## 3. ファイル命名規則

### 3.1 標準形式

```text
<common_name>_<role>.<extension>
```

例：

```text
kyodai_english_2024_sheet.pdf
kyodai_english_2024_answers.pdf
kyodai_english_2024_rubric.md
```

共通名の構成は自由とする。運用上は `<school>_<subject>_<year>` を推奨し、同じ学校・科目・年度の別試験は `session1` などの識別子を共通名に追加する。

```text
kyodai_english_2024_session1_sheet.pdf
kyodai_english_2024_session1_answers.pdf
```

### 3.2 使用可能な文字

ファイル名全体には、半角英数字と `_`、`-`、`.` のみを使用できる。先頭文字は半角英数字とする。全角文字、日本語、空白、パス区切り文字は使用できない。全角文字を半角に自動変換する処理は行わない。

検証式：

```regex
^[A-Za-z0-9][A-Za-z0-9_.-]*$
```

役割の直前の区切りには `_` を使用する。共通名の中では `-` も使用できる。

### 3.3 役割と拡張子

| 役割 | ファイル名の末尾 | 許可する拡張子 | グループ内の件数 |
|---|---|---|---|
| 解答用紙 | `_sheet` | `.pdf` | 必ず1件 |
| 解答解説 | `_answers` | `.pdf`、`.md`、`.txt` | 0件以上 |
| 採点基準 | `_rubric` | `.pdf`、`.md`、`.txt` | 0件以上 |

大文字・小文字は、共通名・役割・拡張子とも区別しない。参照資料の元のファイル名は保存時に維持する。

同名ファイルは1回の選択内で重複できない。例えば `exam_answers.pdf` と `EXAM_ANSWERS.PDF` は重複として扱う。`exam_answers.pdf` と `exam_answers.md` は異なる資料として同時に登録できる。

### 3.4 互換動作と命名上の注意

役割の末尾が認識されないPDFは、拡張子を除いた名前全体を共通名とする解答用紙として扱う。例えば `exam.pdf` は用紙として登録でき、`exam_answers.pdf` とも対応付けられる。

このため、`exam_explanation.pdf` や `exam_answers_v2.pdf` は解答解説とは判定されない。解答解説には必ず `_answers` を拡張子の直前に付ける。版を識別する場合は `exam_v2_answers.pdf` と `exam_v2_sheet.pdf` のように、用紙と資料の共通名をそろえる。

実装では役割を除いた共通名の両端の `_` と `-` を除去する。通常の命名では、この除去に依存する余分な区切り文字を付けない。

## 4. 自動対応付け

### 4.1 判定手順

1. ファイル名の使用可能文字と重複を検証する。
2. 拡張子を除き、末尾の `_sheet`、`_answers`、`_rubric` を判定する。
3. 役割ごとの拡張子を検証する。
4. 役割を除いた共通名を大文字・小文字を区別せず比較し、グループ化する。
5. 各グループの解答用紙がちょうど1件であることを確認する。
6. 用紙と参照資料の対応関係を返す。

曖昧検索、部分一致、翻訳、科目名の同義語判定は行わない。共通名内部の `_` と `-` は別の文字として扱う。

対応関係は今回選択されたファイル内だけで判定する。既存のテンプレートをファイル名で検索して、解説だけを追加する処理は行わない。

### 4.2 判定例

| 選択したファイル | 結果 |
|---|---|
| `exam_sheet.pdf`、`exam_answers.pdf` | 1組として登録可能 |
| `Exam_SHEET.PDF`、`exam_answers.pdf` | 大文字・小文字を区別せず1組として登録可能 |
| `exam_sheet.pdf` | 参照資料なしで登録可能 |
| `exam.pdf`、`exam_answers.pdf` | 互換動作により1組として登録可能 |
| `exam_answers.pdf` | 対応する用紙がないためエラー |
| `exam_sheet.pdf`、`other_answers.pdf` | `other` の用紙がないため選択全体をエラー |
| `exam_sheet.pdf`、`exam.pdf` | 同じ共通名に用紙が2件あるためエラー |
| `exam-a_sheet.pdf`、`exam_a_answers.pdf` | 共通名が異なるためエラー |
| `exam_sheet.png` | 用紙の対応形式外のためエラー |
| `京大_英語_2024_sheet.pdf` | 半角英数字の命名規則に合わないためエラー |

## 5. 登録画面

### 5.1 操作の流れ

1. ホームの「解答用紙を登録」で、用紙と解答解説・採点基準をまとめて選択またはドロップする。
2. システムがファイル名を照合し、用紙名、用紙ファイル、対応する参照資料を表示する。
3. 利用者が対応関係を確認する。
4. 「登録して解答欄を設定」または「N件の用紙を登録」を押す。
5. 登録後、領域エディタで解答欄と設問設定を行う。

複数ページの用紙は、1つのPDFのまま登録する。複数ファイルを結合して1つの用紙にする機能は提供しない。

### 5.2 表示と入力

| 項目 | 動作 |
|---|---|
| ファイル選択 | PDF / Markdown / テキストを複数選択可能。新たな選択は現在の選択を置き換える |
| 対応確認 | ファイル数、用紙数、参照資料数、グループごとの対応関係を表示 |
| 用紙の名前 | 共通名から自動入力。1グループのときだけ変更可能 |
| 管理用ID | 「詳細設定」に配置。空欄が標準。1グループのときだけ指定可能 |
| 複数グループ | 名前とIDの入力を空欄・無効にし、自動設定する |
| 登録ボタン | 対応確認が成功するまで無効 |

用紙の表示名はファイル名の照合キーと独立している。表示名を変更しても、確認済みのファイルの対応関係は変わらない。半角英数字の制約はこの機能に投入するファイル名に適用し、表示名には適用しない。

### 5.3 処理中・完了時

- 照合結果が返る前に選択が変更された場合は、古い照合結果を表示に反映しない。
- 登録中はフォームを無効にし、同じ画面からの二重送信を防ぐ。
- 1グループが成功した場合は、その用紙の領域エディタへ移動する。
- 複数グループが成功した場合は、ホームに各用紙の領域設定リンクを表示する。
- 一部が失敗した場合は、成功した用紙のリンクと失敗理由を表示し、失敗グループだけを再試行対象に残す。
- 通信エラー時は、選択したファイルと入力内容を画面内に保持する。再読み込み後まで保持する機能はない。

## 6. 保存と管理用ID

### 6.1 保存内容

```text
data/templates/<template_id>/
  source.pdf
  blank.pdf
  template.json
  refs/
    kyodai_english_2024_answers.pdf
    kyodai_english_2024_rubric.md
```

| ファイル | 内容 |
|---|---|
| `source.pdf` | 選択した解答用紙の原本 |
| `blank.pdf` | 位置合わせマーカーとページ識別用QRを付けた印刷用PDF |
| `template.json` | ID、表示名、ページ情報、設問情報、既定の参照資料 |
| `refs/` 配下 | 対応付けた解説・採点基準を元のファイル名で保存 |

登録後は `blank.pdf` を印刷して使用する。元の用紙には、生成後の位置合わせマーカーとQRは付いていない。

### 6.2 自動ID

管理用IDが空欄の場合は、用紙ファイル名から拡張子を除いて生成する。役割の `_sheet` はIDに残る。

```text
ファイル名: kyodai_english_2024_sheet.pdf
表示名:     kyodai_english_2024
初回ID:     kyodai_english_2024_sheet
再登録ID:   kyodai_english_2024_sheet-2
```

自動生成の元になる文字列は最大80文字とし、保存先が存在する場合は `-2`、`-3` の順に空いている番号を探す。既存の用紙を上書きしない。自動生成時にWindowsの予約名に該当する場合は `sheet-` を前置する。

管理用IDを明示指定して重複した場合は、自動で変更せず登録失敗として返す。IDを空欄にすると自動採番を利用できる。

### 6.3 参照資料の引き継ぎ

登録時に `template.json` の `default_refs` に、対応する資料の相対パスを保存する。

```json
{
  "default_refs": [
    "refs/kyodai_english_2024_answers.pdf",
    "refs/kyodai_english_2024_rubric.md"
  ]
}
```

領域エディタで設問を追加すると、`default_refs` の内容を新しい設問の `refs` にコピーし、資料のチェックを入れる。利用者は設問ごとにチェックを変更できる。

既存の設問の `refs` は自動で変更しない。`default_refs` がない旧テンプレートでは、空のリストとして扱う。既存の参照資料アップロード操作は、この既定リストを自動更新しない。

## 7. 検証と失敗時の扱い

### 7.1 登録前に選択全体を拒否する条件

- 命名規則に合わないファイル名がある。
- 大文字・小文字を区別せず同名となるファイルが複数ある。
- 役割に対応しない拡張子がある。
- 対応する解答用紙のない参照資料がある。
- 同じ共通名に解答用紙が複数ある。
- 空のファイルがある。
- 複数グループに対して、表示名または管理用IDを指定している。

命名規則などで対応関係が確定できない場合は、その選択の用紙を1件も保存しない。プレビューはファイル名のみを扱うため、空ファイルは画面側と登録APIで検証する。

### 7.2 グループごとに処理する失敗

用紙PDFの破損、パスワード保護、ページ不足、印刷用PDF生成失敗、参照資料の保存失敗などは、該当グループの登録失敗として扱う。他グループの処理は継続する。

失敗グループについて、その処理で新規作成した保存先の削除を試みる。成功したグループと以前から存在する用紙は削除しない。保存先の削除自体に失敗した場合、未完了のファイルが残る可能性がある。

参照資料はファイル名・拡張子・非空を検証する。資料の内容、採点基準の妥当性、資料PDFのパスワードや破損までは、この登録処理では検証しない。

### 7.3 再試行

登録APIから部分成功の結果を受け取れた場合、画面は失敗した用紙とその参照資料だけを残す。再試行時に成功分を再登録しない。

通信断で登録APIの結果を受け取れなかった場合、サーバー側で保存済みかどうかを自動判定する機能はない。同じファイルを再送すると別の管理用IDで登録される可能性がある。登録APIは同じリクエストの再送に対する重複排除を保証しない。

## 8. API

### 8.1 対応関係のプレビュー

```http
POST /api/templates/registration-preview
Content-Type: application/json
```

```json
{
  "filenames": [
    "kyodai_english_2024_sheet.pdf",
    "kyodai_english_2024_answers.pdf"
  ]
}
```

`filenames` は1〜200件。ファイル本体は送信せず、永続化しない。

成功時（HTTP 200）：

```json
[
  {
    "title": "kyodai_english_2024",
    "sheet": "kyodai_english_2024_sheet.pdf",
    "references": ["kyodai_english_2024_answers.pdf"]
  }
]
```

グループは共通名が最初に現れた順、参照資料は投入順で返す。表示名の大文字・小文字は、そのグループで最初に現れたファイルに基づく。

### 8.2 一括登録

```http
POST /api/templates/register-files
Content-Type: multipart/form-data
```

| フィールド | 必須 | 内容 |
|---|---|---|
| `files` | 必須 | 用紙と資料のファイル。複数指定可能 |
| `title` | 任意 | 1グループの場合の表示名。空欄なら共通名 |
| `template_id` | 任意 | 1グループの場合の管理用ID。空欄なら自動生成 |

登録時にもファイル名と対応関係を再検証する。プレビューの結果を保存許可として流用しない。グループごとに順次処理し、完了結果を同期レスポンスで返す。

レスポンス例（テンプレート本体は抜粋）：

```json
{
  "templates": [
    {
      "sheet": "english_sheet.pdf",
      "template": {
        "template_id": "english_sheet",
        "title": "english",
        "default_refs": ["refs/english_answers.pdf"]
      }
    }
  ],
  "failures": [
    {
      "sheet": "math_sheet.pdf",
      "message": "PDFを読み込めませんでした。ファイルを開けるか確認して選び直してください。"
    }
  ]
}
```

### 8.3 HTTPステータス

| 状況 | ステータス | 判定方法 |
|---|---|---|
| プレビュー成功 | 200 | 対応関係の配列 |
| 命名・対応関係・登録前検証のエラー | 400 | `detail` のメッセージ |
| 必須項目不足、プレビュー件数超過などのリクエスト形式エラー | 422 | バリデーションエラー |
| 一括登録の処理完了 | 200 | 必ず `templates` と `failures` の両方を確認 |

一括登録は全グループが失敗しても、グループ処理まで到達していればHTTP 200で `failures` を返す。管理用ID重複も、このAPIでは該当グループの `failures` に含める。

既存の単独作成API `POST /api/templates` は引き続き利用可能とする。このAPIには今回の半角英数字のファイル命名規則を強制せず、既存の日本語ファイル名からの登録も維持する。同APIにおける管理用ID重複はHTTP 409となる。

## 9. 制約と対象外

- 対応付けは用紙全体単位とする。設問番号や解説PDFのページ単位への自動分割は行わない。
- 解答欄の自動検出、配点・正答の自動抽出は行わない。
- 画像からの白紙用紙登録は対象外とする。
- フォルダ単位の取り込み、再帰走査、既存用紙への解説だけの自動追加は行わない。
- `answers` と `rubric` は、どちらも採点時の参照資料として渡す。役割による優先順位は設定しない。
- 通常の画面操作ではプレビューの上限により1〜200ファイルとなる。一括登録API単体には同じ件数上限の明示検証がない。
- この機能独自のファイルサイズ上限・総容量上限は定義していない。大容量登録の性能は保証範囲を定めていない。
- 登録だけでは採点を開始できない。設問と解答領域を設定・保存した用紙をスキャンに使用する。

## 10. 受け入れ条件と検証

| ID | 条件 | 期待結果 |
|---|---|---|
| AC-01 | 半角英数字の同じ共通名で用紙・解説・採点基準を選択 | 1グループとして表示・保存される |
| AC-02 | 英語と数学のファイルをまとめて選択 | 各共通名の資料だけがそれぞれの用紙に対応付く |
| AC-03 | 大文字・小文字だけが異なる共通名 | 同じグループとして扱う |
| AC-04 | 用紙なしの解説、重複用紙、不正な名前・拡張子 | 登録前にエラーになり保存しない |
| AC-05 | プレビューだけを実行 | データ領域に書き込まない |
| AC-06 | 同じ用紙を自動IDで再登録 | 既存用紙を残し、別のIDで保存する |
| AC-07 | 複数用紙の一部が壊れたPDF | 有効な用紙は成功し、失敗した用紙を結果で識別できる |
| AC-08 | 部分成功後に再試行 | 画面から失敗グループのファイルだけを再送する |
| AC-09 | 登録ボタンを連続操作 | 同じ画面で実行中の登録を重複送信しない |
| AC-10 | 遅いプレビューの応答前に選択を変更 | 古い対応関係で新しい表示を上書きしない |
| AC-11 | 対応付け済みの用紙で設問を追加 | `default_refs` が設問の `refs` に引き継がれ、資料が選択される |
| AC-12 | 通信失敗 | 画面内のファイルと入力内容が保持される |
